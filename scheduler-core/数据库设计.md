# Lite-Scheduler 数据库设计方案（参考 Quartz 模块化设计）

## 1. 当前设计分析

### 1.1 现有实体类问题
当前 `TaskDefinition` 类存在以下问题：
- **职责不单一**：同时包含任务定义、调度配置、执行状态等多种职责
- **字段冗余**：调度相关字段（`cron`/`fixedRate`/`fixedDelay`）互斥，会产生大量空值
- **耦合度高**：任务定义与执行状态、调度配置强耦合
- **扩展性差**：新增调度类型需修改核心表结构

### 1.2 设计目标
- **符合三大范式**：消除冗余数据，确保数据一致性
- **模块化设计**：参考 Quartz 架构，按功能拆分表
- **独立解耦**：各模块职责清晰，便于扩展和维护
- **支持多种调度类型**：Cron 表达式、固定频率、固定延迟
- **支持任务生命周期管理**：从定义到执行的完整状态追踪

## 2. 重新设计的数据表方案

### 2.1 核心表结构

#### 2.1.1 任务定义表（`task_definition`）
**职责**：存储任务的基本信息和执行目标
**设计思路**：只保留任务的静态定义，与调度配置、执行状态解耦

| 字段名 | 数据类型 | 主键 | 约束 | 描述 |
|-------|---------|------|------|------|
| `id` | `VARCHAR(64)` | 是 | `PRIMARY KEY` | 任务唯一标识（UUID） |
| `name` | `VARCHAR(128)` | 否 | `NOT NULL` | 任务名称 |
| `group_name` | `VARCHAR(64)` | 否 | `NOT NULL DEFAULT 'default'` | 任务分组 |
| `bean_name` | `VARCHAR(128)` | 否 | `NOT NULL` | Spring Bean 名称 |
| `method_name` | `VARCHAR(128)` | 否 | `NOT NULL` | 执行方法名称 |
| `description` | `VARCHAR(512)` | 否 | - | 任务描述 |
| `async` | `BOOLEAN` | 否 | `NOT NULL DEFAULT TRUE` | 是否异步执行 |
| `enabled` | `BOOLEAN` | 否 | `NOT NULL DEFAULT TRUE` | 任务是否启用 |
| `persistent` | `BOOLEAN` | 否 | `NOT NULL DEFAULT FALSE` | 是否持久化 |
| `created_time` | `DATETIME` | 否 | `NOT NULL DEFAULT CURRENT_TIMESTAMP` | 创建时间 |
| `updated_time` | `DATETIME` | 否 | `NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 更新时间 |

**设计说明**：
- 符合第一、二、三范式：每个字段不可再分，完全依赖主键，无传递依赖
- 仅存储任务的静态属性，与调度和执行状态解耦
- 支持 Spring Bean 方式的任务定义

#### 2.1.2 触发器表（`task_trigger`）
**职责**：存储触发器的通用信息，作为不同触发器类型的父表
**设计思路**：采用继承式设计，支持多种触发器类型扩展

| 字段名 | 数据类型 | 主键 | 约束 | 描述 |
|-------|---------|------|------|------|
| `id` | `VARCHAR(64)` | 是 | `PRIMARY KEY` | 触发器唯一标识（UUID） |
| `task_id` | `VARCHAR(64)` | 否 | `NOT NULL, FOREIGN KEY REFERENCES task_definition(id)` | 关联的任务ID |
| `trigger_type` | `VARCHAR(32)` | 否 | `NOT NULL` | 触发器类型：`CRON`/`FIXED_RATE`/`FIXED_DELAY` |
| `start_time` | `DATETIME` | 否 | - | 触发器开始时间（NULL 表示立即开始） |
| `end_time` | `DATETIME` | 否 | - | 触发器结束时间（NULL 表示永久执行） |
| `priority` | `INT` | 否 | `NOT NULL DEFAULT 5` | 优先级（1-10，5为默认） |
| `enabled` | `BOOLEAN` | 否 | `NOT NULL DEFAULT TRUE` | 触发器是否启用 |
| `created_time` | `DATETIME` | 否 | `NOT NULL DEFAULT CURRENT_TIMESTAMP` | 创建时间 |
| `updated_time` | `DATETIME` | 否 | `NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 更新时间 |

**设计说明**：
- 支持多种触发器类型，便于扩展新的调度方式
- 与任务定义通过外键关联，支持一个任务多个触发器
- 包含通用的触发器属性，如开始/结束时间、优先级等

#### 2.1.3 Cron 触发器表（`task_cron_trigger`）
**职责**：存储 Cron 表达式类型的触发器配置
**设计思路**：仅存储 Cron 特有的配置，与通用触发器信息分离

| 字段名 | 数据类型 | 主键 | 约束 | 描述 |
|-------|---------|------|------|------|
| `trigger_id` | `VARCHAR(64)` | 是 | `PRIMARY KEY, FOREIGN KEY REFERENCES task_trigger(id)` | 关联的触发器ID |
| `cron_expression` | `VARCHAR(128)` | 否 | `NOT NULL` | Cron 表达式 |
| `time_zone_id` | `VARCHAR(64)` | 否 | `NOT NULL DEFAULT 'Asia/Shanghai'` | 时区 |
| `misfire_instruction` | `INT` | 否 | `NOT NULL DEFAULT 0` | 错过执行策略：0-忽略，1-立即执行，2-下次执行 |

**设计说明**：
- 与 `task_trigger` 一对一关联，通过外键确保数据一致性
- 仅存储 Cron 特有的配置，减少冗余
- 支持时区配置和错过执行策略

#### 2.1.4 简单触发器表（`task_simple_trigger`）
**职责**：存储固定频率和固定延迟类型的触发器配置
**设计思路**：合并固定频率和固定延迟配置，通过字段区分

| 字段名 | 数据类型 | 主键 | 约束 | 描述 |
|-------|---------|------|------|------|
| `trigger_id` | `VARCHAR(64)` | 是 | `PRIMARY KEY, FOREIGN KEY REFERENCES task_trigger(id)` | 关联的触发器ID |
| `repeat_count` | `INT` | 否 | `NOT NULL DEFAULT -1` | 重复次数（-1 表示无限循环） |
| `repeat_interval` | `BIGINT` | 否 | `NOT NULL DEFAULT 0` | 重复间隔（毫秒） |
| `simple_type` | `VARCHAR(32)` | 否 | `NOT NULL` | 简单触发器类型：`FIXED_RATE`/`FIXED_DELAY` |
| `misfire_instruction` | `INT` | 否 | `NOT NULL DEFAULT 0` | 错过执行策略：0-忽略，1-立即执行，2-下次执行 |

**设计说明**：
- 支持固定频率和固定延迟两种调度方式
- 重复次数和间隔分开存储，便于计算下次执行时间
- 支持错过执行策略

#### 2.1.5 任务状态表（`task_status`）
**职责**：存储任务的实时执行状态
**设计思路**：与任务定义分离，便于独立更新和查询

| 字段名 | 数据类型 | 主键 | 约束 | 描述 |
|-------|---------|------|------|------|
| `task_id` | `VARCHAR(64)` | 是 | `PRIMARY KEY, FOREIGN KEY REFERENCES task_definition(id)` | 关联的任务ID |
| `last_fire_time` | `DATETIME` | 否 | - | 上次触发时间 |
| `next_fire_time` | `DATETIME` | 否 | - | 下次触发时间 |
| `last_execution_status` | `VARCHAR(32)` | 否 | - | 上次执行状态：`SUCCESS`/`FAILURE`/`NONE` |
| `consecutive_failures` | `INT` | 否 | `NOT NULL DEFAULT 0` | 连续失败次数 |
| `total_executions` | `BIGINT` | 否 | `NOT NULL DEFAULT 0` | 总执行次数 |
| `total_successes` | `BIGINT` | 否 | `NOT NULL DEFAULT 0` | 总成功次数 |
| `total_failures` | `BIGINT` | 否 | `NOT NULL DEFAULT 0` | 总失败次数 |
| `updated_time` | `DATETIME` | 否 | `NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 更新时间 |

**设计说明**：
- 存储任务的实时执行状态，便于监控和统计
- 与任务定义分离，减少锁竞争
- 包含丰富的执行统计信息

#### 2.1.6 任务执行日志表（`task_execution_log`）
**职责**：记录任务的每次执行历史
**设计思路**：保留历史记录，便于审计和调试

| 字段名 | 数据类型 | 主键 | 约束 | 描述 |
|-------|---------|------|------|------|
| `id` | `VARCHAR(64)` | 是 | `PRIMARY KEY` | 日志唯一标识（UUID） |
| `task_id` | `VARCHAR(64)` | 否 | `NOT NULL, FOREIGN KEY REFERENCES task_definition(id)` | 关联的任务ID |
| `trigger_id` | `VARCHAR(64)` | 否 | `FOREIGN KEY REFERENCES task_trigger(id)` | 触发本次执行的触发器ID |
| `start_time` | `DATETIME` | 否 | `NOT NULL` | 执行开始时间 |
| `end_time` | `DATETIME` | 否 | - | 执行结束时间（NULL 表示执行中） |
| `duration_ms` | `BIGINT` | 否 | - | 执行时长（毫秒） |
| `status` | `VARCHAR(32)` | 否 | `NOT NULL` | 执行状态：`RUNNING`/`SUCCESS`/`FAILURE` |
| `error_message` | `TEXT` | 否 | - | 错误信息 |
| `exception_stack` | `TEXT` | 否 | - | 异常堆栈信息 |
| `created_time` | `DATETIME` | 否 | `NOT NULL DEFAULT CURRENT_TIMESTAMP` | 日志创建时间 |

**设计说明**：
- 记录任务的每次执行细节，便于审计和调试
- 包含执行时间、时长、状态和错误信息
- 与任务定义和触发器关联，便于追踪执行上下文

## 4. 设计优势

### 4.1 符合三大范式
- **第一范式**：所有字段不可再分，如 `cron_expression` 直接存储完整表达式
- **第二范式**：非主键字段完全依赖于主键，如 `task_cron_trigger` 的 `cron_expression` 依赖于 `trigger_id`
- **第三范式**：非主键字段不传递依赖，如 `task_status` 的 `last_fire_time` 直接依赖于 `task_id`，不依赖其他非主键字段

### 4.2 模块化设计
- 任务定义与调度配置分离，便于独立管理
- 支持多种触发器类型，便于扩展新的调度方式
- 执行状态与核心定义分离，减少锁竞争
- 执行日志独立存储，便于历史查询和审计

### 4.3 高扩展性
- 新增调度类型只需添加新的触发器子类表
- 新增任务属性只需扩展 `task_definition` 表
- 支持动态添加和修改触发器

### 4.4 高性能
- 表结构精简，减少磁盘空间占用
- 索引设计合理，查询性能优化
- 状态表独立，减少核心表的锁竞争

### 4.5 易维护性
- 职责清晰，便于理解和维护
- 数据一致性强，减少数据冗余
- 支持部分更新，减少全表扫描

## 5. 与 Quartz 设计的对比

| 设计点 | Lite-Scheduler | Quartz |
|-------|----------------|--------|
| 核心思想 | 模块化、解耦、轻量 | 模块化、分布式、功能完整 |
| 任务定义 | 仅支持 Spring Bean | 支持多种任务类型（JobDetail） |
| 触发器类型 | Cron、固定频率、固定延迟 | Cron、简单、日历等多种类型 |
| 分布式支持 | 预留设计（可扩展） | 完整支持 |
| 表数量 | 6张表 | 11张表 |
| 复杂度 | 较低，易于理解 | 较高，功能完整 |
| 扩展性 | 良好，便于扩展新功能 | 优秀，插件化设计 |

## 6. 迁移建议

### 6.1 现有数据迁移
1. 将现有 `task_definition` 表中的基本信息迁移到新的 `task_definition` 表
2. 根据 `cron`/`fixedRate`/`fixedDelay` 字段，创建对应的触发器记录
3. 将执行状态相关字段迁移到 `task_status` 表
4. 执行日志表保持不变

### 6.2 代码调整
1. 修改 `TaskDefinition` 类，移除调度配置和执行状态字段
2. 新增触发器相关实体类：`TaskTrigger`、`CronTrigger`、`SimpleTrigger`
3. 新增任务状态实体类：`TaskStatus`
4. 修改调度逻辑，使用新的表结构进行任务调度
5. 更新持久化服务，支持新的表结构

## 7. 总结

本次设计参考了 Quartz 的模块化设计理念，结合 Lite-Scheduler 的轻量特性，重新规划了数据库表结构。设计符合三大范式，实现了任务定义、调度配置、执行状态的解耦，支持多种调度类型，便于扩展和维护。

该设计既保留了 Quartz 设计的优点，又简化了复杂度，适合 Lite-Scheduler 作为轻量级调度框架的定位。同时，设计预留了分布式扩展的空间，便于后续功能升级。
