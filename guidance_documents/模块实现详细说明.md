### 1. 核心模块 (scheduler-core)

#### 1.1 模块定位

**scheduler-core** 是 Lite-Scheduler 的核心模块，提供了完整的任务调度框架基础能力。它不依赖 Spring（但提供了 Spring 集成），可以独立运行，也可以作为 Starter 引入到 Spring Boot 项目中。

#### 1.3 核心类详解

##### 1.3.1 `@ScheduledTask` 注解

**文件位置**: `com.tuba.schedulercore.annotation.ScheduledTask`

**作用**: 声明式定义定时任务

**核心字段**:
- `name`: 任务名称，为空时使用方法名
- `cron`: Cron 表达式或数字秒（如 "5" 表示每 5 秒）
- `async`: 是否异步执行，默认 `true`
- `group`: 任务分组，默认 `"default"`
- `description`: 任务描述

**使用示例**:
```java
@ScheduledTask(name = "打印时间任务", cron = "0/10 * * * * ?", async = true, description = "每10秒打印一次时间")
public void printTime() {
    System.out.println("当前时间: " + LocalDateTime.now());
}
```

##### 1.3.2 `TaskDefinition` 类

**文件位置**: `com.tuba.schedulercore.model.TaskDefinition`

**作用**: 封装任务的元数据和执行信息

**核心属性**:
```java
private String id;              // 任务唯一标识（UUID）
private String name;             // 任务名称
private String group = "default";  // 任务分组
private String cron;              // Cron 表达式或数字秒
private boolean async = true;     // 是否异步执行
private Object bean;             // Spring Bean 实例
private Method method;           // 要执行的方法
private String description;      // 任务描述
private boolean enabled = true;  // 是否启用
private List<TaskPlugin> plugins; // 任务级插件
```

##### 1.3.3 `ThreadPoolScheduler` 类

**文件位置**: `com.tuba.schedulercore.scheduler.ThreadPoolScheduler`

**作用**: 基于 ThreadPoolTaskScheduler 实现任务调度

**核心功能**:
- 支持 Cron 表达式和数字秒（固定频率）两种调度模式
- 管理所有已调度任务的 `ScheduledFuture`，支持取消任务
- 实现 `DisposableBean` 接口，支持优雅关闭
- 支持立即触发任务执行

**调度逻辑**:
```java
public void schedule(TaskDefinition definition) {
    // 检查任务是否启用
    if (!definition.isEnabled()) return;
    
    // 创建 Runnable
    Runnable runnable = () -> {
        TaskContext ctx = new TaskContext(definition);
        taskExecutor.execute(ctx);
    };
    
    // 解析 Cron 表达式或数字秒，创建 Trigger
    Trigger trigger = parseTrigger(definition.getCron());
    
    // 调度任务并保存 ScheduledFuture
    ScheduledFuture<?> future = taskScheduler.schedule(runnable, trigger);
    scheduledFutures.put(definition.getId(), future);
}
```

##### 1.3.4 `SimpleTaskExecutor` 类

**文件位置**: `com.tuba.schedulercore.executor.SimpleTaskExecutor`

**作用**: 实现任务执行的核心逻辑

**核心功能**:
- 支持同步/异步执行模式
- 调用插件链的生命周期方法
- 处理任务执行异常
- 生成任务执行日志
- 支持无参方法和带 `TaskContext` 参数的方法

**执行流程**:
```
invokeAndHandle():
1. 设置开始时间
2. 调用 PluginManager.before() → 所有插件的 before()
3. 反射调用任务方法
4. 设置结束时间
5. 调用 PluginManager.after() 或 onError()
6. 创建 TaskLog（待持久化）
```

#### 1.4 执行流程

```
1. 应用启动 → 所有 Spring Bean 初始化完成
2. TaskRegistrar.onApplicationReady() → 扫描所有 Bean，查找 @ScheduledTask 方法
3. 创建 TaskDefinition → 注册到 TaskRegistry
4. Scheduler.schedule() → 解析 Cron 表达式，调度任务
5. 定时触发 → 创建 TaskContext，调用 TaskExecutor.execute()
6. 执行任务 → 调用插件链，反射执行任务方法
7. 生成日志 → 创建 TaskLog（待持久化）
```

### 3. 插件模块 (scheduler-plugins)

#### 3.1 模块定位

**scheduler-plugins** 是 Lite-Scheduler 的插件扩展模块，提供了可扩展的插件机制，允许用户自定义任务执行的前后处理逻辑。

#### 3.2 核心功能

| 功能 | 实现类/接口 | 文件位置 | 说明 |
|------|-------------|----------|------|
| 插件接口 | `TaskPlugin` | `com.tuba.schedulercore.plugin.TaskPlugin` | 定义插件生命周期回调 |
| 插件管理器 | `PluginManager` | `com.tuba.schedulercore.plugin.PluginManager` | 管理所有插件，统一调用 |

#### 3.3 插件开发示例

**自定义插件实现**:
```java
@Component
public class MyCustomPlugin implements TaskPlugin {
    
    @Override
    public void before(TaskContext context) {
        System.out.println("任务执行前：" + context.getDefinition().getName());
    }
    
    @Override
    public void after(TaskContext context) {
        System.out.println("任务执行成功：" + context.getDefinition().getName());
    }
    
    @Override
    public void onError(TaskContext context, Throwable e) {
        System.err.println("任务执行失败：" + context.getDefinition().getName());
        e.printStackTrace();
    }
}
```

**插件执行顺序**:
- 所有插件的 `before()` 方法按注册顺序执行
- 任务方法执行
- 成功时执行所有插件的 `after()` 方法
- 失败时执行所有插件的 `onError()` 方法

##### 4.2.2 `TaskController` 类

**文件位置**: `com.tuba.schedulersamples.TaskController`

**作用**: 演示如何通过 REST API 动态管理任务

**核心功能**:
- 获取所有任务列表
- 启用/禁用任务
- 立即触发任务执行

**核心代码**:
```java
@RestController
@RequestMapping("/api/tasks")
public class TaskController {
    
    @Autowired
    private TaskRegistry taskRegistry;
    
    @Autowired
    private Scheduler scheduler;
    
    // 获取所有任务
    @GetMapping
    public List<TaskDefinition> getAllTasks() {
        return new ArrayList<>(taskRegistry.getAll());
    }
    
    // 启用任务
    @PostMapping("/{id}/enable")
    public void enableTask(@PathVariable String id) {
        taskRegistry.enable(id);
        TaskDefinition def = taskRegistry.get(id);
        scheduler.schedule(def);
    }
    
    // 禁用任务
    @PostMapping("/{id}/disable")
    public void disableTask(@PathVariable String id) {
        taskRegistry.disable(id);
        scheduler.unschedule(id);
    }
    
    // 立即触发任务
    @PostMapping("/{id}/trigger")
    public void triggerTask(@PathVariable String id) {
        TaskDefinition def = taskRegistry.get(id);
        scheduler.triggerNow(def);
    }
}
```

## 📝 开发规范

1. **任务方法设计**:
   - 推荐使用无参方法或单参数 `TaskContext`
   - 避免使用多参数方法
   - 方法应简洁明了，只包含核心业务逻辑

2. **异常处理**:
   - 任务方法中应适当捕获异常
   - 重要异常应记录日志
   - 不要吞掉异常，让框架处理

3. **异步执行**:
   - 长时间运行的任务应使用异步执行
   - 短时间任务可使用同步执行

4. **任务分组**:
   - 合理使用任务分组，便于管理和查询
   - 相同业务类型的任务归为一组

## 🎯 总结

Lite-Scheduler 是一个轻量级的任务调度框架，具有以下特点：

1. **轻量级设计**：核心代码简洁，依赖少
2. **注解驱动**：基于注解 `@ScheduledTask` 声明任务，使用方便
3. **灵活的调度方式**：支持 Cron 表达式和固定频率调度
4. **异步执行**：支持任务异步执行，提高系统吞吐量
5. **插件扩展**：提供任务执行的扩展点，方便自定义逻辑
6. **优雅关闭**：支持任务的优雅关闭，避免任务丢失
7. **任务上下文**：提供任务执行上下文，方便传递执行信息
8. **自动注册**：自动扫描 Spring 容器中的任务并注册
9. **支持 AOP**：支持 Spring AOP 代理，不影响任务执行

Lite-Scheduler 适合中小型项目的定时任务需求，也可以作为学习调度框架原理的好案例。
